# OfferTrack - 秋招投递助手

OfferTrack 是一个用于管理秋招、校招和实习投递记录的 Microsoft Edge 扩展。

打开招聘网站的“我的投递 / 投递记录 / 应聘记录 / 我的申请”等页面后，OfferTrack 会自动读取页面中的公司、岗位、地点、投递时间和当前流程状态，并在同步前提供预览。确认无误后，可以一键写入自己的飞书多维表格。后续再次访问同一投递页面时，插件会尽量识别已有记录并更新状态，减少重复维护表格的工作。

## 主要功能

- 自动识别招聘网站中的投递记录
- 提取公司、岗位、地点、投递时间、状态等信息
- 同步前预览解析结果
- 自动生成唯一记录 ID，减少重复记录
- 已有投递状态变化时更新飞书记录
- 支持飞书多维表格 `/base/` 链接
- 支持飞书知识库中的多维表格 `/wiki/` 链接
- 可手动覆盖个别网站的公司名称
- 可对验证过的网站开启自动同步
- 页面右下角提供轻量入口：默认收起，点击后才展开同步面板

# 一、安装到 Microsoft Edge

1. 解压 `OfferTrack_Edge_v1.5.1.zip`。
2. 在 Edge 地址栏打开：

   `edge://extensions/`

3. 打开右侧或左侧的“开发人员模式”。
4. 点击“加载解压缩的扩展”。
5. 选择解压后的 `OfferTrack_Edge_v1.5.1` 文件夹。
6. 建议把 OfferTrack 固定到 Edge 工具栏，方便随时查看解析结果和进入设置。

如果以后只是升级 OfferTrack，并且希望继续使用现有飞书配置，可以把新版文件覆盖到当前插件目录，然后在 `edge://extensions/` 中点击 OfferTrack 的“重新加载”。

---

# 二、创建飞书自建应用

OfferTrack 使用你自己的飞书企业自建应用访问你的多维表格。

## 1. 打开飞书开放平台

在浏览器打开：

`https://open.feishu.cn/app?lang=zh-CN`

登录自己的飞书账号。

## 2. 创建企业自建应用

在开发者后台：

1. 进入“企业自建应用”。
2. 点击“创建企业自建应用”。
3. 应用名称可以填写：`OfferTrack` 或 `OfferTrack 秋招投递助手`。
4. 应用描述可以简单填写：`同步个人招聘投递记录到飞书多维表格`。
5. 创建完成后进入应用后台。

OfferTrack 不需要配置网页应用主页、机器人主页或小程序页面；本插件主要通过飞书 OpenAPI 读写你自己的多维表格。

## 3. 获取 App ID 和 App Secret

进入：

`基础信息 / 凭证与基础信息`

找到：

- `App ID`，通常以 `cli_` 开头
- `App Secret`

把这两个值填写到 OfferTrack 的“设置 → 飞书应用”中。

App Secret 相当于应用密码，请只用于自己的插件配置，不要公开到网页、代码仓库或截图中。

---

# 三、配置飞书 API 权限

进入飞书开放平台中该应用的：

`开发配置 → 权限管理`

OfferTrack 使用的是 **应用身份** 调用飞书 API，因此申请权限时请选择/确认权限作用于“应用身份”。

## 推荐开通的权限

### 1. 多维表格权限

搜索并开通：

`查看、评论、编辑和管理多维表格`

Scope：

`bitable:app`

这是 OfferTrack 读取字段、创建字段、读取记录、新增记录和更新记录时使用的主要权限。

### 2. 如果使用 `/wiki/` 多维表格链接

如果你的多维表格地址类似：

`https://xxx.feishu.cn/wiki/xxxxxxxx?table=tblxxxxxxxx`

还需要开通：

`查看知识空间节点信息`

Scope：

`wiki:node:read`

因为 OfferTrack 需要先把 Wiki 节点解析成真正的多维表格 App Token。

如果使用的是普通：

`https://xxx.feishu.cn/base/appxxxxxxxx?table=tblxxxxxxxx`

通常不需要额外的 Wiki 节点权限。

## 3. 让权限正式生效

开通权限后检查权限状态。

如果后台提示“待发布”或要求发布新版本，请进入：

`应用发布 / 版本管理与发布`

创建并发布一个新版本，使新申请的权限生效。

如果刚修改过权限，建议在 `edge://extensions/` 中点击 OfferTrack 的“重新加载”，然后再测试连接。

# 四、创建飞书多维表格

1. 在飞书中新建一份“多维表格”。
2. 名称可以使用：`2027届秋招投递记录`。
3. 不需要提前创建所有列，OfferTrack 可以自动初始化表头。
4. 打开这份多维表格，并复制浏览器地址栏中的完整链接。

OfferTrack 支持两种常见地址：

普通多维表格：

`https://xxx.feishu.cn/base/app...?...table=tbl...`

知识库中的多维表格：

`https://xxx.feishu.cn/wiki/...?...table=tbl...`

---

# 五、把飞书应用添加到多维表格

只有 OpenAPI 权限还不够，OfferTrack 对应的飞书应用还需要拥有这份多维表格本身的访问权限。

打开目标多维表格，在页面右上角：

`... → ...更多 → 添加文档应用`

然后：

1. 搜索刚才创建的 `OfferTrack` 应用。
2. 添加该应用。
3. 给应用足够的编辑权限。
4. 如果这份多维表格开启了“高级权限”，建议给 OfferTrack **可管理** 权限，否则字段创建或记录写入可能被拒绝。

如果“添加文档应用”里搜索不到 OfferTrack，请先确认：

- 应用已经至少开通一个多维表格 API 权限，例如 `bitable:app`
- 新权限已经正式生效
- 如果飞书要求发布应用版本，已经完成发布
- 应用的可用范围包含这份文档的所有者

# 六、在 OfferTrack 中连接飞书

打开 Edge 工具栏中的 OfferTrack，进入“设置”。

## 1. 飞书应用

填写：

- App ID
- App Secret

## 2. 多维表格

把刚才复制的完整多维表格地址粘贴到“多维表格链接”。

然后依次点击：

1. `从链接解析`
2. `测试连接`
3. `初始化表头`
4. `保存设置`

“从链接解析”会自动获取或填写：

- App Token
- Table ID

如果连接成功，插件会显示当前表格字段数量。

## 3. 初始化表头

OfferTrack 会准备以下字段：

- 公司
- 岗位名称
- 工作地点
- 投递时间
- 当前状态
- 招聘平台
- 岗位链接
- 最近更新时间
- 下一步行动
- 面试时间
- 优先级
- 备注
- 唯一记录ID
- 原始状态

“下一步行动”“面试时间”“优先级”“备注”主要用于你在飞书中继续维护求职进度。

# 七、日常使用

1. 打开招聘官网的“我的投递 / 投递记录 / 应聘记录 / 我的申请”等页面。
2. 等页面加载完成约 1～3 秒。
3. OfferTrack 会自动解析当前页面。
4. 页面右下角只会显示一个小的 OfferTrack 图标和记录数量，不会自动弹出完整面板。
5. 点击右下角小图标，展开同步面板。
6. 也可以点击 Edge 工具栏中的 OfferTrack 图标查看更完整的解析预览。
7. 检查公司、岗位、地点、投递时间和状态。
8. 确认无误后点击“同步到飞书”。

页面悬浮面板点击 `×` 后会收起到右下角小图标，后续网页动态刷新或 DOM 变化不会自动重新展开。同步成功后，面板也会在短暂显示结果后自动收起。

# 八、状态和去重

OfferTrack 会把不同招聘网站的状态尽量统一为：

- 已投递
- 筛选中
- 笔试/测评
- 面试中
- Offer
- 已结束
- 已撤回

同时保留“原始状态”，方便回看招聘网站的原始流程文字。

同步时插件会根据页面中的申请 ID 或岗位、平台、投递时间等信息生成唯一记录 ID，用于判断：

- 新投递：新增记录
- 已存在但状态变化：更新记录
- 信息没有变化：跳过

---

# 九、公司名称修正

招聘网站展示公司名的方式并不统一。如果某个网站自动识别出的品牌名不符合你的习惯，可以进入：

`设置 → 高级解析设置 → 公司名覆盖`

填写网站域名和你希望保存的公司名，例如：

`example.jobs.feishu.cn → 示例科技`

之后该域名会优先使用你设置的公司名称。

# 十、常见问题

## 1. 提示缺少 `wiki:node:read`

你使用的是 `/wiki/` 链接。回到飞书开放平台“权限管理”，为应用身份开通“查看知识空间节点信息（wiki:node:read）”。

## 2. 提示缺少 `bitable:app`

为应用身份开通“查看、评论、编辑和管理多维表格（bitable:app）”，确认权限已生效，并重新加载 OfferTrack。

## 3. API 权限已经开了，但还是没有权限写表

检查目标多维表格右上角：

`... → ...更多 → 添加文档应用`

确认 OfferTrack 已被添加，并且拥有编辑权限；开启高级权限的表格建议授予可管理权限。

## 4. 页面解析结果不准确

先不要同步。在 Edge 工具栏打开 OfferTrack 查看预览；如果只是公司名不理想，可以用“公司名覆盖”。如果岗位、地点、状态等字段有系统性问题，可以保留页面截图和解析结果用于进一步优化通用解析规则。

---

OfferTrack 的定位很简单：把散落在各个招聘官网里的投递记录整理到一张持续更新的飞书多维表格里，让秋招进度更容易维护和回看。
