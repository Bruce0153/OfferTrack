# OfferTrack v1.5.0

一个面向秋招/实习投递记录管理的 Microsoft Edge 扩展。

打开招聘网站的“我的投递 / 投递记录 / 我的申请”等页面后，OfferTrack 会自动解析投递记录，在插件中预览，再去重同步到飞书多维表格。

## v1.5.0：通用解析器 3.0

本版仍然**没有为京东、快手、小鹏、智元等网站添加专用 Adapter**。修复集中在通用解析原则：

1. **先找“申请事件”，再找岗位**：记录候选必须同时具备岗位标题和投递日期/状态/流程等申请信号；单独的导航、职类标签不会生成记录。
2. **岗位标题与职类标签分离**：`数据与算法类`、`研发 - 算法`、`通用智能板块`、`专场招聘会投递`、单独的 `实习生` 等不再被当作岗位标题。
3. **公司品牌从页面级信息推断**：优先 Meta、Title、Logo/Header，并增加页面左上品牌文字识别；`应届`、`校招`、`板块/事业部/职类` 等上下文词不会再作为公司名。
4. **终态优先**：卡片存在 `已结束/未通过/不合适/淘汰` 时，优先于流程图里的 `录用评估/offer` 等阶段标签。
5. **流程阶段不是当前状态**：`录用评估`、`面试`、`简历筛选` 只有带 active/current/fail 等状态信号时才参与当前状态判断。
6. **更严格的候选过滤**：低置信度和非角色型标题直接过滤，不允许污染飞书。
7. **预览更完整**：Popup 除了公司/岗位/状态，现在同时显示地点与投递时间，便于同步前核对。

## 重要说明

- 第一次在一个新招聘网站上使用时，请先看插件预览，再同步。
- 若页面完全没有暴露中文公司品牌，而你希望飞书使用中文名，可在设置中的“公司名覆盖”填写一次域名 → 公司名。
- 旧版本已经写入飞书的错误行不会自动删除；确认新版预览正确后手动删除旧错误行一次即可。

## v1.5.0：为什么公司名更稳定

OfferTrack 不再只从某一个 DOM 文本猜公司，而是把多个来源当作“证据”：页面 Header/Logo、左上角可见品牌、`og:site_name` / `application-name`、页面标题，以及页面可能提供的 JSON-LD 结构化数据。多个候选会经过招聘词清洗、营销前缀清洗、品牌根一致性和视觉位置评分后再选择最终展示名。

典型清洗示例：

- `加入影石创新科技股份有限公司` + 页面左上 `影石Insta360` → 优先 `影石Insta360`
- `快手校招` → `快手`
- `小鹏汽车校招官网` → `小鹏汽车`
- `欢迎加入智元AGIBOT！` → `智元AGIBOT`（若 Header 有更明确品牌则 Header 优先）
- `深圳；接受调剂到其他城市` → `深圳`

此外，本版的语义 UID 不再把“公司展示名”作为主键组成部分，因此品牌名清洗规则升级时不会轻易造成重复记录。
